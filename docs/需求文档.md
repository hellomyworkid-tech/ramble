# 随口记（Ramble）需求文档 v1

> 名称：中文 **随口记**，英文 **Ramble**（意为“随口说”）。Bundle ID `com.zengji.suikouji`。上架前需在 App Store Connect 确认名称未被占用。
> 图标：「四色声波」，四根圆角竖条依次是待办（蓝）、笔记（青）、账本（绿）、提醒（橙），提供浅色、深色、着色三种版本。
> 最后更新：2026-10-11

## 1. 产品定位

一款 **AI 驱动的生活事务与财务助手**。用户可以随口说、随手打，内容零碎杂乱、夹杂“嗯、啊、那个”都没关系，AI 负责理解并整理成结构化记录：**待办、账目、账单、到期提醒**，再按规则准时提醒。

| 项目 | 决定 |
|---|---|
| 发布方式 | 上架 App Store，**第一版不上中国大陆**（销售范围取消勾选中国大陆）；以后再看 ICP 备案和生成式 AI 的要求 |
| 界面语言 | 简体中文 + 英文（String Catalog，已完成，约 1,040 条；英文复数和语序用 substitution 处理） |
| 设备 | 只做 iPhone（TARGETED_DEVICE_FAMILY = 1）。iPad 上系统会用兼容模式运行 iPhone 版。**iPhone Duo（折叠屏）**：用 iOS 27.1 SDK 编译，展开后铺满内屏、工具栏和标签栏立在侧边；工具栏按钮都带图标（只有文字的按钮在侧边栏里放不下，会被收进「…」）；窗口短边 ≥ 600pt（Duo 内屏 626pt）时允许横屏，普通 iPhone 和 Duo 外屏仍只竖屏（Duo 展开后是横着的，只竖屏的话会横躺着显示） |
| 最低系统 | iOS 26（端侧大模型 Foundation Models 和新语音识别 SpeechAnalyzer 需要） |
| 技术栈 | Swift 6 + SwiftUI + SwiftData，原生开发 |
| 数据 | SwiftData + CloudKit 私有库同步（数据存在用户自己的 iCloud，没有自建数据库） |
| 收费 | 免费 + Pro 订阅（StoreKit 2） |
| 开发者账号 | 暂无，之后注册。在此之前只用本地存储开发，CloudKit 等注册后再开 |

## 2. 核心：AI 快速录入

### 2.1 输入方式
- **语音**：默认用 Apple 端侧语音识别（SpeechAnalyzer），边说边出文字，免费且离线
  - **说话语言**：跟随系统 / 中文（普通话）/ English，在「设置 › 语音识别」里选
  - **可选开源模型：通义千问 Qwen3-ASR**（阿里，Apache 2.0 许可，可商用），通过 mlx-audio-swift（MIT 许可，代码放在 Vendor/mlx-audio-swift，补丁见 RAMBLE-PATCHES.md）在手机 GPU 上用 MLX 运行，下载后完全离线。提供 0.6B（8 位，约 1.0GB，推荐）和 1.7B（4 位，约 1.6GB，8GB 内存机型，方言口音更准）两种，模型来自 Hugging Face 的 mlx-community。点麦克风立即开始录音，模型同时载入（首次约 1～2 秒），预览每秒刷新一次：已经说完的部分在停顿处（12～24 秒之间最安静的 0.4 秒）识别定稿、不再重读，每次只重读最后不到 24 秒，录多长都一直出字；说完后把最后一段再识别一次（原来是每次重读整段、超过 60 秒就不再更新）；输出自带标点，繁体转简体；每次输出按录音长度设上限，防止卡在重复里。模型载不进（多半是内存不足）时这次录音停止并提示，之后改用 iPhone 自带的识别；切到后台时释放内存。录音时屏幕常亮；锁屏或切走时麦克风停下，已说的保留，回到前台后识别完（后台不能用 GPU），App 不在前台时预览暂停。**内存：同一时间只放一个大模型**——用语音模型录音时不预载整理模型，整理模型要载入时先放掉空闲的语音模型（10 月 15 日实测两个一起约 3.3GB，8GB 的 iPhone 只剩约 66MB 空闲，系统开始杀别的进程，上划回桌面卡顿）。模拟器里不能用。**用完一分钟后释放**（10 月 21 日加）：整理模型（约 2.3GB）和语音模型（约 1GB）在最后一次使用 60 秒后自动放掉，不再一直留到 App 退到后台（手机内存报告显示，只留整理模型时随口记也占 2.5GB，空闲内存只剩约 100MB，系统在杀别的 App）；再用时重新载入，多等一两秒
  - **为什么不用 Whisper 了**：v1 用的 Whisper Large v3（WhisperKit 压缩版 626MB）实测中文很差。同一组测试录音（6 句口述，系统中文语音合成，干净/加噪声两版，按字算错误率，去掉标点、数字写法统一）：Qwen3-ASR 0.6B 8 位 干净 0.9% / 嘈杂 1.4%；1.7B 4 位 0.5% / 2.4%；iPhone 自带 2.8% / 3.8%；Whisper 3.8% / 19.8%，而且大多没有标点。Qwen 官方公布的成绩也一致（词错误率，越低越好）：WenetSpeech 会议 0.6B 6.88、Whisper-large-v3 19.11；方言 KeSpeech 7.08 对 28.79；极端噪声 17.88 对 63.17。测试录音不是真人说话，真人口述以手机实测为准
  - **手机实测**（iPhone 16 Pro Max，0.6B 8 位）：下载加检查约 3.4 分钟（Wi‑Fi），载入 1.3 秒，8 秒的录音识别约 0.75 秒；12 段测试录音全部带标点、几乎没有错字。和 Qwen3 4B 同时在 GPU 上运行不出错，AI 模型正在载入的那几秒里第一次识别慢一些（约 4 秒）
  - 旧版下载的 Whisper 模型在「语音识别」和「已下载的模型」里显示为「旧版 Whisper 模型」，可以一键删除；之前选了 Whisper 的会先改回 iPhone 自带的识别
  - **没选的模型**：SenseVoice、Paraformer（FunASR）权重许可写着“仅供参考和学习”，商用上架有风险；FireRedASR2（Apache 2.0）中文也强，但模型更大，作为备选；Belle-whisper 只是 Whisper 的中文微调，没有现成的手机版本
- **文字**：随手输入一段话
- **快捷入口**：首页悬浮麦克风按钮、小组件、Siri / 快捷指令、锁屏控件

### 2.2 理解与整理
同一段话可以拆出 **多条、不同类型** 的记录：

> 输入：“嗯…那个今天中午吃饭花了三十五，啊对，还有信用卡十五号要还，大概两千多吧，然后护照好像明年三月到期”
>
> 整理结果：
> 1. 💸 支出 ¥35 · 餐饮 · 今天
> 2. 🧾 账单：信用卡还款 · 每月 15 日 · 约 ¥2,000 ⚠️金额待确认
> 3. 🪪 到期：护照 · 2027 年 3 月 ⚠️具体日期待确认

AI 需要做到：
- 去掉口头禅、重复和自我纠正（“三十…不对，四十”最终取 40）
- 判断类型：待办 / 收入 / 支出 / 转账 / 账单 / 到期 / 应收 / 应付（「张三还欠我两千」「还欠装修师傅三千工钱月底给」）
- 提取字段：金额、币种、分类、账户、日期（理解“后天”“月底”“下周五”等相对说法）、重复规则、提前提醒
- 把不确定的字段标出来，让用户确认
- **自动分类与补全**：根据用户以往的修改学习习惯（如“星巴克 → 餐饮/咖啡、用 Visa 卡”），作为上下文提供给模型
- **分类一定填上**：要求模型给每笔收支、账单选最接近的分类；模型给了不存在的分类名（「装修」）或没给时，按说的内容里的关键词猜（瓷砖、暖气 → 居住；手机费 → 通讯，按命中的字数打分，「铺车暖气」里的「车」不会压过暖气和瓷砖）；还猜不出就放进「其他」并标为待确认。模型选了「购物」「其他」这类兜底分类、但内容明显属于别的分类时（买瓷砖），按关键词改
- **一共花了多少只记一次**：「铺暖气和买瓷砖一共花了八万二」，本机模型有时拆成两笔、每笔都是八万二；同样金额的几笔如果原话里这个数只说了一次，合成一笔「铺车暖气和购买瓷砖」
- **欠的钱不算收支**：说的是「欠我」「借给」「还没收到」「我欠」「跟谁借了」「还没付」这类话时，记成应收/应付而不是收入/支出，并取出对方（张三、装修师傅）；本机模型把它记成笔记或待办时也会改过来。「收回欠款」「还清了」「话费欠费」「信用卡欠款」不会误判

### 2.3 保存方式：先确认再保存
每条记录显示成一张可编辑卡片，可以改字段、换类型、删除，确认后一键全部保存。

### 2.4 混合模型方案（M3 已实现）
```
          输入文本 + 上下文（现在时间/时区/账户/分类/已有账单和证件）
                         │
             ┌───────────▼───────────┐
             │ 端侧 Foundation Models │  免费 · 离线 · 隐私
             │ 结构化输出 @Generable  │
             └───────────┬───────────┘
          以下情况改走云端 ↓
   · 机型不支持 Apple Intelligence、未开启或模型还在下载
   · 端侧结果校验失败（没解析出内容、缺标题、金额不是数字、日期不合法）
   · 设置为「仅云端」
                         │
             ┌───────────▼───────────┐
             │ 用户自带 API Key 直连   │  Claude / ChatGPT / Gemini / 自定义接口
             │ Key 只存在本机钥匙串    │  不经过我们的服务器
             └───────────────────────┘
```
- 处理方式三档：自动（默认）/ 仅本机 / 仅云端。设置页只显示当前档位用得到的部分：「仅本机」隐藏云端，「仅云端」隐藏本机模型
- **本机模型二选一**：Apple Intelligence（免下载，但中文口语整理效果一般），或**开源模型**：阿里通义千问 Qwen3 4B（约 2.3GB，8GB 内存机型）/ Qwen3 1.7B（约 1GB，6GB 内存机型，明显不如 4B 准，建议配合「自动」），Apache 2.0 许可。通过苹果 MLX 框架和 iOS 27 的 Foundation Models 第三方模型接口运行，复用同一套 @Generable 结构化输出并做语法约束，输出一定合法。需要 iOS 27；切到后台时释放模型内存；申请了「提高内存上限」权限
- **开源模型在手机上的做法**（手机上读提示约每秒几百字、写约每秒 10～20 字，提示越长越慢）：给模型的说明压到最短，附一个与真实内容无关的示例；只让模型写类型、名称、金额、原话里的时间词、分类，日期由程序从时间词推算，账单/证件种类和提醒天数按名称规则补；「花了」记支出、「要还/要交」记账单；整理后的文字漏掉原话 15% 以上或多出原话没有的内容（如回显说明）时，改用规则清理后的原文；提醒标题去掉「提醒：」「记得」。每次输出按输入长度设上限，防止小模型卡在空白里（1.7B 曾因此耗时 3.5 分钟）；「仅本机」下被截断时整理退回规则清理结果
- **输出稳定（重要修复）**：MLX 库把输出格式转成 JSON 时字段顺序每次随机，模型就按随机顺序写字段（有时先写名称再定类型），同一句话每次结果不同。已在项目内带一份打过补丁的 mlx-swift-lm（`Vendor/mlx-swift-lm`，说明见其中 RAMBLE-PATCHES.md），按 @Generable 声明的顺序（x-order）排列；同一句话现在每次结果一致，语法编译也能复用缓存。升级该库时要检查上游是否已修
- **笔记整理（本机开源模型）**：用中文的简短要求，只让模型写整理后的文字；不通过检查（漏句、改数字、没加标点、改成「用户反映」、夹英文）时再按「只去口头禅」整理一次，仍不行则在「自动」模式下交给云端，否则用规则清理后的原话。提醒由规则从整理后的文字里找：有将来的时间词、又有要做的动作（要、去、交、签、复查、开始…）的分句，去掉时间词作为标题
- **一句话记录（本机开源模型）**：按「然后」「还有」等也切分句子（口述常没标点）；金额只认自己那一句里的时间（「明天复查，挂号费花了五十」的挂号费不会记到明天）；已经花了的钱不会记到将来；名称是「note」「笔记」这类占位词时，从原话里取；去掉「添加一个笔记」「记一下」这类说给 App 的话；笔记里提到将来要做的事而模型没列出时，补一条待办；笔记内容在结果页显示后，后台用模型理顺成通顺的句子（用户已改过就不覆盖）
- **分类兜底**：AI 给的分类不在用户的分类里时（如「装修」），按关键词猜内置分类（瓷砖、装修 → 居住），对所有 AI 都有效；详见 2.2「分类一定填上」
- **重新整理**：「整理结果」页（首页记一下、笔记整理）都有「重新整理」：本机模型换一种随机方式再整理一次（不会和上次一样），云端模型多想一档；本机处理时如果设置了云端，还可以「用 某某 整理」
- **一键清空**：首页记一下、追问回答、笔记输入栏、问一问的输入框右侧有 ⓧ，一点清空（录音时隐藏）
- 调试工具：Mac 上可以用同一个模型、同样的提示词和输出格式批量跑（模拟器测试 PromptDumpTests 导出 App 实际使用的提示词），真实输出存为测试用例（NoteTidyFixtures、OpenCaptureFromDictationTests）
- 实测（iPhone 16 Pro Max，Qwen3 4B）：一句话记账/记事约 15 秒，笔记一段整理约 11～15 秒，测试句子类型、金额、日期、提醒全部正确；Qwen3 1.7B 约 5～10 秒，但会漏记、照抄示例、偶尔返回空结果
  - 修复字段顺序后（10 月 15 日，同一台手机）：调试版 一句话记录 5～10 秒、笔记整理 8.5～9.7 秒；**发布版（Release）笔记整理 4.6～7.1 秒**，一句话记录 4.7～9.8 秒；装到手机上自用也用发布版
- **模型下载走系统后台下载**（AI 整理和语音识别的开源模型都是）：**只在 Wi‑Fi 下下载**（模型 1～2GB，不走流量和热点；没连 Wi‑Fi 时任务等着，连上自动继续）；锁屏、切到别的 App、App 被系统关掉都会继续；断网后自动续传（最多重试 5 次）；下载完成后，下次回到 App 时自动做一次检查（载入试运行；语音模型再识别一秒静音），检查要在前台进行
- 本机结果再过一遍规则清理（嗯、呃、句首的「然后那个」等），只删明确的口头禅，不删「那个人」「然后去吃饭」这类正常用法
- 云端默认模型：Claude Opus 5.5（effort low）、gpt-6-astra、Gemini 3.8 Flash；验证 Key 后可从账户拉取全部可用模型，也可以手填模型 ID
- **自定义接口（第三方 API）**：设置 › AI 整理 › 自定义接口，接任何兼容 OpenAI Chat Completions 格式的服务。填接口地址（一般以 /v1 结尾，App 自动加 /chat/completions；粘贴完整地址也会自动截回）、API Key、模型 ID，可起个显示名称
  - 常用服务一键填地址：DeepSeek、通义千问（阿里云百炼兼容模式）、Kimi、智谱 GLM、豆包（火山方舟）、硅基流动、OpenRouter（地址已逐个确认可访问）；验证 Key 时从接口的 /models 拉取模型列表
  - 只接受 https；局域网里自己运行的服务（Ollama 等）可以用 http（Info.plist 开了 NSAllowsLocalNetworking 和本地网络权限说明），本地服务不需要 Key 时随便填一个
  - 结构化输出：各家共同支持的是 JSON 模式（`response_format: json_object`），所以把输出格式的 JSON Schema 写进说明；不支持 JSON 模式的服务返回 400 时自动去掉它重发一次；回复里包了 ```json 也能读。图片用 image_url、PDF 用 file 发送（服务不支持时会报错）
  - 同意弹窗写明发给哪个域名（如 api.deepseek.com）；思考强度不适用于自定义接口
- **云端提速**：按模型关掉或调低「思考」——Gemini 3.x Flash `thinkingLevel: low`（3.8 Flash 默认 medium，是变慢的主因），Flash-Lite `minimal`，2.5 Flash `thinkingBudget: 0`；OpenAI GPT-5 `minimal`、5.1+ `none`、GPT-6 `low`。Gemini 的输出格式只要求必填的 type 和 title，不再逐项写出 20 多个空字段。结果页显示用时（如「Gemini 处理 · 2.1 秒」）
- **云端思考强度**（设置 › AI 整理，只在用到云端时显示）：**自动（默认）**/ 快速 / 均衡 / 深入。自动按内容定档，不额外调用 AI 判断：
  - 记一下：去掉口头禅后不超过 40 个字一律快速；超过 120 字、6 个以上分句、4 个以上数字或有改口（不对、应该是、改成）才用均衡；最高均衡
  - 笔记整理：200 字以内快速，否则均衡；最高均衡
  - 读文件：小票、一两行字的照片快速；一般文件均衡；超过 8000 字、6 页或 4 个文件用深入
  - 快速的结果没通过检查（解析失败、没整理出内容、字段不合法）时，自动高一档重试一次；网络、Key、额度错误不重试；固定档位时不重试
  - 结果页在非快速档时显示所用档位，如「Gemini 处理 · 均衡 · 4.2 秒」
- 各档按各家参数换算——Claude effort low/medium/high；Gemini 3.x Flash low/medium/high、Flash-Lite minimal/low/high、2.5 Flash 思考预算 0/2048/8192；GPT-6 low/medium/high、GPT-5.1+ none/low/medium、GPT-5 minimal/low/medium；GPT-4.x 不支持则不发。请求超时随档位放宽到 90/120/180 秒。本机模型不受影响（始终不思考）
- 三家都用 JSON Schema 结构化输出；Claude 在 Opus 5.5 / Sonnet 5.5 上开启服务端拒答回退（`fallbacks: "default"`）
- 第一次用云端前弹窗征得同意（App Store 审核要求），设置里可以关闭。**同意是按服务商给的**：换成另一家、或自定义接口换了域名，会再问一次（用户同意的是把文字发给某一家，不是任何一家）
- 提到已有的账单或证件时，默认更新那一条而不是重复添加
- 原计划的 Cloudflare Workers 代理暂不需要；以后如果要提供「不用自己申请 Key」的托管额度（Pro），再加回来

### 2.5 分阶段
- **第一版**：AI 录入整理 + 自动分类与补全
- **第二版（已实现）**：自然语言查询（“这个月吃饭花了多少”）、定期总结与建议（周报/月报、异常支出提醒）

### 2.6 问一问（第二版）
- 入口：今天页顶部的「问问你记过的」搜索条（在本月支出、待办数字上方，带示例问题）；「记一下」里输入的像问题时出现「这像是在提问，点这里查一查」；Siri「问随口记」；链接 `ramble://ask?q=…`
- **先规则、后 AI，数字永远在手机上算**：常见问法（花了多少、钱花在哪、最贵的一笔、日均、几笔、和上期比、收入、结余、待办/完成/过期、账单、到期）由规则直接读懂，不联网、瞬间出结果；规则读不懂的才交给 AI，AI 只返回「查什么」（主题、度量、时间、分类、关键词），只发送问题本身，不发送账目
- 时间说法：今天/昨天/前天/明天、本周/上周/上上周/下周、本月/上个月/下个月、今年/去年、上下半年、最近 N 天/周/月/年、N 月（份）、某年某月、某月某日、一共/至今；周从周一开始
- 分类：用户自己的分类名优先，其次日常说法（吃饭→餐饮、打车→交通…）；商户和具体东西（咖啡、滴滴、房租）先在备注里找，找不到再按所属分类统计
- 进行中的时期和上一期**同期**比较（本月前 13 天对比上个月前 13 天）
- 问笔记内容（「血脂多少」「装修下一步做什么」）：在笔记里找相关的几段，交给 AI 只根据这几段回答，并列出出处可点开；没有 AI 时直接列出相关笔记。发送到云端前沿用首次同意
- 回答卡片：一句话结论 + 对比/日均/预算余额 + 分类占比条或明细，标注「本机计算」或「某 AI 理解问题 · 数字在本机计算」
- **问答记录**（10 月 19 日加）：问过的问题和回答存在本机（Application Support/ask-history.json，最多 100 条，不同步、不进备份），再打开问一问时按天显示在上面，停在最新一条。以前的回答是当时的数字，下面写「回答于 几点」，点「重新问」按现在的记录再算；长按可以重新问、拷贝回答、删除；右上角可以清空全部记录。Siri「问随口记」问的也记进来

### 2.7 周报 / 月报（第二版）
- 入口：今天页「回顾」（显示上周/本月支出和同期对比）、通知（每周一 9:00 周报、每月 1 日 9:00 月报，可在设置 › 提醒里关）、Siri「看随口记周报」、链接 `ramble://report?kind=week|month`
- 默认打开刚结束的一期（当期过了 3 天/7 天以上则打开当期），可前后翻
- 内容：支出（与上一期或同期对比）、收入、结余、日均；月预算使用；钱花在哪（分类占比和变化）；最大的几笔；完成/新增/过期待办；笔记条数与重点；接下来的账单和到期
- 「值得注意」自动生成：支出变化、明显上涨或新出现的大类（异常支出提醒）、单笔占比过大、预算快用完或超支、分类预算超支、过期待办、接下来要付的账单
- 「AI 点评」手动触发：只发送合计和分类金额（不发每笔备注），返回两三句总结和至多两条建议；同一期数字不变时缓存，不重复请求

## 3. 功能模块

### 3.1 事务待办
- 标题、备注、截止日期时间、优先级、分类/标签、子任务
- 重复规则与提前提醒（见第 4 节）
- 视图：今天 / 即将到来 / 全部 / 已完成

### 3.2 日常记账
- 类型：支出、收入、转账
- **多账户**：现金、借记卡、信用卡（账单日/还款日/额度）、电子钱包等
- **分类**：两级分类，自带默认分类，可以自定义图标和颜色
- **多币种**：每个账户有自己的币种；记账可以用任意币种，按记账当天的汇率换算到主币种汇总
  - 汇率来自 ExchangeRate-API 免费接口（无需 Key，每天更新，需标注「Rates By Exchange Rate API」），本机缓存，离线时用上次的汇率；每笔可手动改
  - 切换主币种时，按最新汇率重算所有已有记录
- **预算**：月度总预算 + 分类预算，接近或超出时提醒
- **统计（M4 已实现）**：账本页左上角「统计」，按月或按年
  - 月：每日支出柱状图 + 日均线，拖动查看每天；预算执行；最大的几笔
  - 年：每月收支分组柱状图 + 按月明细表
  - 支出构成：按金额排序的列表（不用饼图——十几个分类做饼图分不清），点进去看该分类的每一笔
  - 配色经过色盲安全校验：支出蓝 / 收入橙，深色模式单独取值
- **拍照与附件（M4 已实现）**：记账可以附小票照片，到期提醒可以附证件照片
  - 「扫小票记一笔」：本机 Vision 识别文字，自动填金额（优先 实付 > 应付 > 合计，忽略 实收/现金/找零）、商家和日期，只填空着的字段，需要你核对

- **应收应付（应收未收、应付未付）**：别人欠你的、你欠别人的钱先记在「账本 › 应收应付」，不算进收入支出和统计
  - 记：金额、币种、对方（谁欠我/欠谁）、事项、预计收付日期（可不填）、收到/付出时用的分类和账户、备注；也可以直接说「张三还欠我两千」
  - **一个按钮变成收支**：每条右边有「收到了」/「付了」，点一下就把剩下的金额按今天、预设的分类和账户记成一笔收入/支出，底部提示可以「撤销」；分几次收付时长按（或左滑）选「收到一部分…」，可以改金额、日期和账户
  - 已收/已付由关联的账目算出来：在账本里删掉某一笔，它会回到「应收应付」里；收齐后移到「已结清」
  - 账本页本月汇总下方显示「应收 ¥… · 应付 ¥…」，点进去看全部；过了预计日期的标出来
  - 跟账单的区别：账单是周期性的、按期提醒的付款（房租、信用卡）；应收应付是一次性的欠款、借款、垫付、尾款

### 3.3 账单与还款
- 周期性账单：信用卡、房租、水电、贷款月供、订阅续费等
- 预估金额（可以每期不同）、付款账户、分类
- **账单与记账联动**：点「已支付」后自动生成一笔支出（可以改实付金额），提醒自动推到下一期
  - 信用卡还款记为「付款账户 → 信用卡」的**转账**，不算支出：刷卡消费已经记过支出，再记一次会重复计算
- 列表按到期日排序，逾期的突出显示

### 3.4 到期提醒
- 类型：证件（身份证/护照/驾照/签证）、保险、合同、保修、会员等，也可以自定义
- 到期日、证件照片附件、备注
- 默认提醒节点：提前 90 / 30 / 7 天 + 当天，可以修改
- 续期后一键更新下一次的到期日

### 3.5 笔记（时间线式）
用来记长期跟踪的事（装修、看病复查、孩子成长、车辆保养、项目进展）和参考资料（wifi 密码、联系方式、会议纪要）。

- **说给 App 听的话不进笔记**（10 月 23 日加）：「在装修这个笔记条目下加一条：」「往装修笔记里记一下」「装修笔记加一条」「记到装修里」（开头或结尾）只用来选笔记，不写进记录。手机上按规则去掉（不管哪个 AI 整理的），也写进了 AI 的要求；动词后面要跟「一下/一条」或标点，所以「在公司楼下记得买咖啡」「我的笔记写得很乱」不会被误删
- **结构**：一个笔记 = 标题 + 按时间追加的一条条记录。每条记录带日期，可以很长，可以附图片和文档；只有一条记录时就是普通备忘录。笔记可以置顶、搜索（包括图片和 PDF 里识别出的文字）
- **看照片、存到相册**（10 月 19 日加）：点照片进全屏查看，可以双指或双击放大、左右滑看同一条记录里的其他照片，下面有「分享」和「存储到相册」两个按钮；长按缩略图也能直接「存储到相册」。存的是 App 里保存的那份（JPEG，长边最多 2048 像素，添加时就缩小了，原图不保留）。第一次存时系统只请求「仅添加照片」权限，App 看不到相册内容。PDF 等文件仍用系统预览打开
- **给某句话设提醒**：在记录里选中一句 → 设提醒 → 生成一条**关联待办**，出现在待办列表和今天页，照常通知、完成、重复；笔记里这句话带下划线和提醒标记，待办里显示「来自：装修记录」，点开跳回原文
- **AI 语音整理**：在笔记里说话或打字后点「整理」，确认后才保存。两种方式（设置 › AI 整理 › 笔记整理）：
  - **理顺语句（默认）**：按意思把口述写成通顺的书面句子，补标点、去重复和说了一半又改口的地方、理顺前后颠倒的顺序，保持本人口吻，事实和数字一个不少、不添加。本机模型的结果要过检查：说过的数字（含「两千一百八」「二点一」这类中文数字）必须都在、不能多出新数字，长度相近，原话里的实词基本都在（合并重复不算丢，漏掉一个分句会被发现）；不过关就退回只去口头禅。云端结果数字不对时自动加强重试一次
  - **只去口头禅**：只去「嗯」「然后那个」和重复，原话说法不动
  - 同时找出有时间点的句子，建议设提醒
- **说给 App 听的话**：「给这条标记一下重点」「划重点」「标为重要」「加个星标」不算笔记内容，会从文字里去掉，并在确认页自动打开「标为重点」（规则识别，本机和云端都有效；云端 AI 也会识别其他说法）。笔记里直接保存、首页「说点什么」生成的笔记同样适用；「这件事很重要」这类说法会标重点但保留原话
- **首页自动归档**：首页「说点什么」的内容如果属于某个已有笔记，AI 会整理成一条记录追加进去（或新建笔记），和待办、记账一起出现在确认页，可以改归属或去掉。例：「装修那边师傅说下周三能铺砖，今天买瓷砖花了三千二」→ 追加到「装修记录」+ 下周三提醒（关联原句）+ ¥3,200 居住支出
- **附件**：照片、截图、扫描件，以及 PDF、Word、Excel 等任意文件（单个 ≤ 50MB），用系统预览打开；图片和 PDF 的文字在本机识别，用于搜索
- **不重复提醒**：笔记里已有的未完成提醒不会被「整理」再次建议；首页录入时，同一天同名的未完成待办会提示「已有待办」并默认不新建（可以关掉开关另建一条）
- **入口**：底部「笔记」标签；首页「说点什么」→ 手动添加 → 笔记；笔记页内的输入栏取代全局的「说点什么」栏
- **重点**：长按或右滑一条记录 →「标为重点」，整条记录显示琥珀色底和「★ 重点」标签；「高亮某句话」像荧光笔一样标出句子（黄色底并加粗，不只靠颜色区分），编辑记录时也能高亮任意选中的文字。笔记页右上角 ★ 切换「只看重点」，笔记列表显示每个笔记的重点条数

### 3.6 AI 读文件（图片 / PDF）
把体检报告、化验单、合同、保修卡、发票等交给 AI，自动总结要点记进笔记，并建议相关记录。

- **支持的文件**：照片、PDF（含扫描件）、纯文本，以及 Word（.docx）、Excel（.xlsx）、PowerPoint（.pptx）。Office 文件在手机上直接解压读取：Word 保留段落和表格（单元格用「|」分隔），Excel 每个工作表逐行读出、日期按单元格格式转成 YYYY-MM-DD，PowerPoint 按页读出。旧版 .doc/.xls/.ppt 和 Pages/Numbers 不支持，提示先导出
- **触发**：手动点「AI 读一下」，不自动读。入口：「记一下」输入框里的回形针（加了照片或文件后，「整理」变成「AI 读一下」，可一次选多张照片）；笔记输入栏添加文件后出现的按钮；已保存的记录长按 →「AI 读附件」
- **附带的话**（10 月 20 日加，原来「AI 读文件或照片」是单独一项，不能写字）：和文件一起打的字或说的话交给 AI 当要求和背景，比如「这是上个月的电费单，记一笔」「只记保修到期日」「放进装修记录」，和默认做法冲突时以这些话为准，但事实仍只来自文件和这些话。只要了别的记录（一笔支出、一个提醒）时可以不写总结笔记。照片里没有文字（拍的是东西不是文件）但写了话时，照样交给 AI。结果页顶上显示这段话。笔记里同样：加了文件再在输入框打字，点「AI 读一下」时这些字一起交给 AI，保存后清空
- **第一步，在手机上识别文字**：照片和扫描版 PDF 逐页用 Vision 识别（最多 30 页），有文字层的 PDF 直接读取，显示页数进度。Word / Excel 暂不支持，提示导出为 PDF 或截图
- **第二步，AI 总结**：只发送识别出的文字，**18 位身份证号先在手机上隐去**。短文件先交给本机模型，长文件压缩成标题加异常和结论行再试，不行再交给云端 AI（沿用 AI 模式设置和首次发送同意）
- **识别效果差时**（字数远少于页数应有的量）：询问是否把**原件**发给云端 AI 直接看（Claude / ChatGPT / Gemini 都支持图片和 PDF，合计 ≤ 15MB）。每次都单独确认，明确告知原件里的姓名、证件号会发给哪家服务商。没配置云端 AI 时引导去设置。结果页也可以选「识别不准？让 X 看原件重读」
- **总结格式**：第一行写文件是什么、出具方、日期，下面每行一个要点。体检/化验只列异常项（数值、单位、↑↓、参考范围），加上医生结论和建议的原文；合同/保单/保修写双方、金额、起止日期、付款安排、售后电话；发票写商家、金额、日期。**只摘录，不诊断、不给建议**，结果页标注「数字请对照原件核对」
- **顺带生成的记录**（在确认页逐条确认）：复查/随访 → 关联待办（和总结里那一句关联）；合同、保修到期 → 到期提醒；按月付款 → 账单；发票 → 记一笔。已有的同名同日待办、账单、到期项不会重复添加
- **存放位置**：从笔记里读，总结就是这个笔记的一条新记录，原件附在这条记录上（未命名的笔记会用 AI 建议的名字）；对已保存的附件读，总结追加到附件所在的那条记录；从首页读，由 AI 选一个已有笔记或新建。去掉笔记那条时，原件改为附在到期提醒或账目上；如果都没有，就提示「这些文件不会保存」

### 3.6.1 iCloud 同步
- 用 SwiftData + CloudKit 私有数据库（容器 `iCloud.com.zengji.suikouji`），在登录同一 Apple 账户的设备间同步全部记录和附件；数据在用户自己的 iCloud 里，我们的服务器不经手。设置 › 数据 › iCloud 同步：开关（默认开，改动在重新打开 App 后生效）、iCloud 账户状态、上次同步时间、错误原因（空间已满、没登录、没网络）
- 打不开 CloudKit 时退回本机存储，不会打不开 App
- **默认分类和账户去重**：每台新设备第一次打开都会自己生成「餐饮」「现金」等默认项，同步后会出现两份。每台设备记下自己生成的那份，所有设备都保留最早创建的一份；每台设备只删除自己生成的重复项，并先把它下面的账目、预算、账单、子分类移到保留的那份上，从不删别的设备的，所以不会在别的设备的数据还没传过来时把它们的分类弄丢。同一分类的两个预算保留最新设的
- 收到其他设备的改动后：重新排提醒、刷新小组件。提醒在每台设备上都会响，在一台上完成，另一台跟着取消
- 不同步：下载的模型、API Key、各项设置
- 「从备份恢复」在开着同步时会把其他设备的数据也换成备份，确认框里有说明
- **上架前**：在 CloudKit Console 把开发环境的数据结构部署到生产环境；以后改数据模型只能加字段（可选或带默认值），不能删改已有字段

### 3.7 界面细节
- 列表里左滑删除时用居中的确认框，并引用要删的那条内容（iOS 26 的确认菜单会指向它所依附的视图，挂在整个列表上会指错行）
- 金额显示：主币种用简短符号（¥82,000.00，不受手机地区影响显示成 CN¥），外币保留能区分的写法（US$12.00）；账本顶部支出用大字，收入和结余分两栏

## 4. 提醒规则
- **提前多次提醒**：每条可以设多个提醒节点（如提前 3 天 + 当天 9:00）
- **灵活重复**：每天 / 每周几 / 每两周 / 工作日 / 每月某日 / 每月最后一天 / 每年某月某日 / 自定义间隔，可以设结束条件
- 不做农历
- 技术约束：iOS 每个 App 最多同时排队 **64 条本地通知**。需要一个调度器，只排最近的 64 条，在 App 打开和后台刷新时补排
- 通知上可以直接操作：完成、稍后提醒、标记已付

**上架必需（需要你在网页上操作）**
- **CloudKit 正式环境**：开发时数据模型是在 CloudKit 的 Development 环境自动建的，TestFlight 和 App Store 版本用的是 Production 环境，**不部署就没法同步**。做法：icloud.developer.apple.com › 选容器 iCloud.com.zengji.suikouji › Schema › **Deploy Schema Changes** 到 Production。以后每次数据模型有改动（加字段、加表）上架前都要再部署一次；改动只能是「加」，不能删字段、改类型

- **App 隐私（营养标签）**：按 Apple 的定义，「收集」指开发者或其合作方能拿到的数据；本 App 没有服务器，AI 服务商是用户自己选、自己付费的，可以填「不收集数据」，并在隐私政策里说明 BYOK 的情况（这是我的理解，提交时再对照 Apple 当时的说明）

## 7. 数据模型（草案）
- `TaskItem`：标题、备注、截止时间、优先级、标签、子任务、重复规则、提醒节点、完成时间
- `Account`：名称、类型、币种、初始余额、信用卡额度、账单日、还款日
- `Category`：名称、图标、颜色、收/支、上级分类
- `Transaction`：类型、金额（Decimal）、币种、汇率、账户、转入账户、分类、日期、备注、附件、关联账单
- `Budget`：周期、金额、分类（为空表示总预算）
- `Bill`：名称、预估金额、币种、账户、分类、重复规则、下次到期日、提醒节点、自动记账开关
- `Outstanding`（应收应付）：方向（应收/应付）、事项、对方、金额、币种、预计日期、分类、账户、备注；结清它的账目（`LedgerEntry.outstanding`）
- `ExpiryItem`：名称、类型、到期日、提醒节点、附件、备注
- `Attachment`：图片（外部存储）、识别出的文字
- `Recurrence`（值类型）：频率、间隔、星期、每月第几天（-1 表示最后一天）、结束条件
- `CategoryHint`：关键词 → 分类/账户的习惯映射（来自用户的修改）

> 兼容 CloudKit：所有属性要可选或有默认值，不用唯一约束，关系都设为可选。
